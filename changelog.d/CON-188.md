- With **Per-language Smaily accounts**, an automation no longer starts the workflow at the top of the Automations tab for a language that has no workflow of its own. That workflow belongs to none of the language accounts, but it was posted through the contact's language account, which started the wrong workflow or was refused. Such a contact now gets the workflow of the **Default fallback account**'s language, through that account; with none there, the contact is skipped, and the Log names the language. The Automations tab hides the workflow at the top in this mode and lists, under **Some languages have no workflow**, each switched-on automation with the languages it has no workflow for. Saving the Automations tab in one per-language mode also keeps the other mode's saved workflows, so a switch back finds them.
