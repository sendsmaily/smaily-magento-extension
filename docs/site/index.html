OverviewÜlevaade

Smaily Connect links your Magento store to Smaily email marketing and, optionally, to Smaily Campaign Intelligence for personalized product recommendations. Smaily Connect ühendab sinu Magento poe Smaily e-turundusega ja soovi korral Smaily Campaign Intelligence'iga, mis pakub personaalseid tootesoovitusi.

What is Smaily Connect?Mis on Smaily Connect?

Smaily Connect for Magento 2 is an extension for Magento Open Source, Adobe Commerce and Mage-OS. It links your store to your own Smaily email-marketing account and, optionally, to Smaily Campaign Intelligence — Smaily's recommendation engine for personalized products and purchase-based automations.

It does four things:

  • Syncs contacts — your newsletter subscribers (or, if you choose, every customer) reach your Smaily contact list, and an unsubscribe in Smaily comes back to Magento.
  • Triggers automations — store events (welcome, first order, abandoned cart) start your Smaily workflows.
  • Powers recommendations — when you connect Campaign Intelligence, your catalog, customers and orders (and, if you switch it on, browsing) feed personalized recommendations and engine-run automations.
  • Serves a product RSS feed — for the RSS block of the Smaily template editor.

Your data stays yours. Contacts live in your Smaily account; the extension only connects the two systems.

Smaily Connect for Magento 2 on laiendus platvormidele Magento Open Source, Adobe Commerce ja Mage-OS. See ühendab sinu poe sinu enda Smaily e-turunduse kontoga ja soovi korral Smaily Campaign Intelligence'iga — Smaily soovitusmootoriga, mis pakub personaalseid tooteid ja ostupõhiseid automaatikaid.

See teeb nelja asja:

  • Sünkroonib kontakte — sinu uudiskirja tellijad (või soovi korral kõik kliendid) jõuavad sinu Smaily kontaktide nimekirja ning Smailys tehtud loobumine jõuab tagasi Magentosse.
  • Käivitab automaatikaid — poe sündmused (tervitus, esimene tellimus, hüljatud ostukorv) käivitavad sinu Smaily töövood.
  • Toidab soovitusi — kui ühendad Campaign Intelligence'i, toidavad sinu kataloog, kliendid ja tellimused (ning soovi korral sirvimine) personaalseid soovitusi ja mootoris töötavaid automaatikaid.
  • Pakub toodete RSS-voogu — Smaily mallide redaktori RSS-ploki jaoks.

Sinu andmed jäävad sinu omaks. Kontaktid asuvad sinu Smaily kontol; laiendus ainult ühendab kaks süsteemi.

How the pieces fit togetherKuidas osad kokku sobivad

There are three systems:

  • Magento — your store: customers, newsletter subscribers, orders, products and storefront activity.
  • Smaily — your email-marketing account, where contacts and automation workflows live (yourcompany.sendsmaily.net).
  • Campaign Intelligence — Smaily's recommendation engine. Optional, connected with a one-time setup link from Smaily.

Smaily Connect is the bridge. Store events reach the extension; the extension queues contacts and automation triggers for Smaily and — if connected — catalog, customer and order data for Campaign Intelligence. Magento's cron sends the queue, normally within a minute.

Under the hood

All background work runs in Magento's cron, in its own smaily_connect cron group. A delivery that fails is retried on its own, so nothing is lost when Smaily or Campaign Intelligence is briefly out of reach. Every delivery shows in Marketing > Smaily Connect > Log.

Süsteeme on kolm:

  • Magento — sinu pood: kliendid, uudiskirja tellijad, tellimused, tooted ja tegevus poes.
  • Smaily — sinu e-turunduse konto, kus asuvad kontaktid ja automaatikate töövood (sinufirma.sendsmaily.net).
  • Campaign Intelligence — Smaily soovitusmootor. Valikuline, ühendatakse Smailylt saadud ühekordse seadistuslingiga.

Smaily Connect on sild. Poe sündmused jõuavad laienduseni; laiendus paneb kontaktid ja automaatikate päästikud Smaily jaoks järjekorda ning — kui ühendatud — kataloogi-, kliendi- ja tellimusandmed Campaign Intelligence'i jaoks. Järjekorra saadab välja Magento cron, tavaliselt minuti jooksul.

Kapoti all

Kogu taustatöö käib Magento cronis, laienduse oma cron-grupis smaily_connect. Ebaõnnestunud saadetist proovitakse ise uuesti, nii et kui Smaily või Campaign Intelligence on korraks kättesaamatu, ei lähe midagi kaduma. Iga saadetis on näha menüüs Turundus > Smaily Connect > Logi.

Before you startEnne alustamist

You need:

  • A Magento store on a supported version (below). The admin footer shows the Magento version on every page ("Magento ver. 2.4.x"); on the server, bin/magento --version prints it and php -v prints the PHP version — run it with the same PHP that runs bin/magento.
  • Magento cron running every minute. The extension does all its sending from cron. Without it, nothing reaches Smaily.
  • A Smaily account with API access. Create an API user in Smaily under Preferences > API — you'll need the subdomain, the API username and the API password. The account's package must include API access.
  • (Optional) A Campaign Intelligence setup link — a one-time link on https://intelligence.smaily.com/…, provided by Smaily if you use the recommendation add-on.

Getting startedAlustamine

Install the extension, then work through the five-step initial setup in the admin. Paigalda laiendus ja läbi halduses viiesammuline algseadistus.

Install the extensionLaienduse paigaldus

The recommended way is composer. Until 3.0.0 is released, give the release candidate's exact version, as the releases page names it: composer require smaily/smailyformagento without a version installs the old 2.8.1, and ^3.0 does not install a release candidate on a standard Magento project, which accepts stable versions only. From 3.0.0 on, composer require smaily/smailyformagento is enough.

Run the commands from the Magento root, as the user that owns the Magento files. bin/magento deploy:mode:show shows the mode. In production mode:

bin/magento maintenance:enable
composer require smaily/smailyformagento:3.0.0-rc10
bin/magento module:enable Smaily_Connect
bin/magento setup:upgrade
bin/magento setup:di:compile
bin/magento setup:static-content:deploy en_US   # every locale your store uses
bin/magento maintenance:disable
bin/magento cache:flush

Keep maintenance mode on until the last command: until setup:static-content:deploy has run, every storefront and admin page fails.

In developer or default mode, composer require, module:enable, setup:upgrade and cache:flush are enough.

Without composer, install the release ZIP into app/code/Smaily/Connect. The full steps — checking the download, production and developer mode, cron, updating and removing — are in INSTALLING.md.

After the install, the admin notifications show Smaily Connect is ready to set up, with a Read Details link to this guide. Finishing the initial setup marks it read.

Upgrading from Smaily for Magento 2.8.x? See Upgrading from 2.8.x first.

Soovitatav viis on composer. Kuni 3.0.0 väljalaskeni anna väljalaskekandidaadi täpne versioon, nagu väljalasete leht selle nimetab: composer require smaily/smailyformagento ilma versioonita paigaldab vana 2.8.1 ja ^3.0 ei paigalda tavalises Magento projektis väljalaskekandidaati, sest see lubab ainult stabiilseid versioone. Alates versioonist 3.0.0 piisab käsust composer require smaily/smailyformagento.

Pärast paigaldust näitavad halduse teated Smaily Connect on seadistamiseks valmis koos lingiga Read Details, mis viib sellesse juhendisse. Algseadistuse lõpetamine märgib teate loetuks.

If your store has several websitesKui poel on mitu veebisaiti

With more than one Magento website, the initial setup opens with Which website are you setting up? Pick the website and press Continue. Each website has its own Smaily connection, contact sync and automations; run the initial setup again for each website you want to connect. On Settings, a Website selector next to the tabs picks the website whose values you see and edit; picking a website that has not finished the initial setup opens that website's initial setup, and so does a link to Dashboard or Log for it. A store with one website never sees either.

Campaign Intelligence is one connection for the whole installation, whichever website is selected. Each product is sent to it once, with the price and link of your default website (or of the first website the product is sold on).

Kui sul on rohkem kui üks Magento veebisait, algab algseadistus küsimusega Millist veebisaiti seadistad? Vali veebisait ja vajuta Jätka. Igal veebisaidil on oma Smaily ühendus, kontaktide sünkroonimine ja automaatikad; läbi algseadistus uuesti iga veebisaidi jaoks, mida soovid ühendada. Ühe veebisaidiga pood kumbagi ei näe.

Campaign Intelligence on kogu paigalduse peale üks ühendus, olenemata valitud veebisaidist. Iga toode saadetakse sinna üks kord, vaikimisi veebisaidi hinna ja lingiga (või esimese veebisaidi omaga, kus toodet müüakse).

Step 1 — Connect your Smaily accountSamm 1 — Ühenda oma Smaily konto

Open Marketing > Smaily Connect > Initial setup. The step list on the left shows the five steps; a step you have completed stays open, so you can move back and forth.

  1. Enter the Subdomain — if your Smaily URL is https://demo.sendsmaily.net, the subdomain is demo. Pasting the full URL also works.
  2. Enter the API username and API password of your Smaily API user. The password is stored encrypted.
  3. Press Test connection. It checks the credentials as typed, without saving; a success also loads your workflows for step 3.
  4. If your store languages use different Smaily accounts or workflows, pick how under How is Smaily organized for your store languages? — see Multilingual stores. A single-language store does not see this.
  5. Shoppers buy on a separate (headless) storefront? Open Using a separate storefront? and enter its address as Storefront URL now — see Using a separate storefront?.
  6. Press Continue. The step is saved, even if Smaily did not accept the credentials; the last step then tells you so.

A finished setup reopens on this step as a summary marked Completed; Edit credentials brings the form back.

Ava Turundus > Smaily Connect > Algseadistus. Vasakul olev sammude loend näitab viit sammu; tehtud samm jääb avatuks, nii et saad edasi-tagasi liikuda.

  1. Sisesta Alamdomeen — kui sinu Smaily URL on https://demo.sendsmaily.net, on alamdomeen demo. Sobib ka täieliku URL-i kleepimine.
  2. Sisesta oma Smaily API kasutaja API kasutajanimi ja API parool. Parool salvestatakse krüpteeritult.
  3. Vajuta Testi ühendust. See kontrollib sisestatud kasutajaandmeid ilma salvestamata; õnnestumisel laaditakse ka sammu 3 töövood.
  4. Kui sinu poe keeled kasutavad eri Smaily kontosid või töövooge, vali see küsimuse Kuidas on Smaily sinu poe keelte jaoks korraldatud? all — vt Mitmekeelsed poed. Ühekeelne pood seda ei näe.
  5. Ostjad ostavad eraldi (headless) poe veebilehel? Ava Kas pood töötab eraldi veebilehel? ja sisesta selle aadress kohe väljale Poe veebilehe aadress — vt Kas pood töötab eraldi veebilehel?.
  6. Vajuta Jätka. Samm salvestatakse ka siis, kui Smaily kasutajaandmeid vastu ei võtnud; viimane samm ütleb sulle siis selle.

Lõpetatud seadistus avaneb uuesti sellel sammul kokkuvõttena märkega Lõpetatud; Muuda kasutajaandmeid toob vormi tagasi.

Step 2 — ContactsSamm 2 — Kontaktid

Contact synchronization to Smaily. This is a lawful-basis choice: pick the mode that matches how you have asked your customers for permission.

  • Subscribers only (consent) — Recommended. Only newsletter subscribers are synced, and unsubscribes in Smaily come back to Magento.
  • All customers (legitimate interest) — every registered customer is synced (soft opt-in).
  • Checkout opt-in only — only shoppers who tick the newsletter checkbox at checkout.

Then pick the extra fields and the checkout options, and press Continue. Saving this step switches contact sync on — except for a website whose contact sync is off: there the step shows Sync contacts to Smaily unticked, and saving keeps sync off unless you tick it. Each option is explained under Settings › Contacts.

Another integration already syncs subscribers?

If another module or service already sends your newsletter subscribers or opt-outs to Smaily, switch it off once this step is saved — not before, so no opt-out is missed in between.

Kontaktide sünkroonimine Smailysse. See on õigusliku aluse valik: vali režiim, mis vastab sellele, kuidas oled klientidelt luba küsinud.

  • Ainult turunduskirjade tellijad (nõusolekuga) — Soovitatud. Sünkroonitakse ainult uudiskirja tellijad ning Smailys tehtud loobumised jõuavad tagasi Magentosse.
  • Kõik kliendid (õigustatud huvi) — sünkroonitakse iga registreeritud klient (pehme nõusolek).
  • Ainult kassas turunduskirjade nõusoleku andnud kontaktid — ainult ostjad, kes märgivad kassas uudiskirja märkeruudu.

Seejärel vali lisaväljad ja kassa valikud ning vajuta Jätka. Selle sammu salvestamine lülitab kontaktide sünkroonimise sisse — välja arvatud veebisaidil, kus kontaktide sünkroonimine on väljas: seal näitab samm valikut Sünkrooni kontaktid Smailysse ilma linnukeseta ja salvestamine jätab sünkroonimise välja, kui sa linnukest ei pane. Iga valikut selgitab jaotis Seaded › Kontaktid.

Kas mõni teine lõiming juba sünkroonib tellijaid?

Kui mõni teine moodul või teenus saadab juba sinu uudiskirja tellijaid või loobumisi Smailysse, lülita see välja pärast selle sammu salvestamist — mitte varem, et vahepeal ükski loobumine kaduma ei läheks.

Step 3 — AutomationsSamm 3 — Automaatikad

Map store events to Smaily automations. For each event — Welcome, First order, Abandoned cart — tick Enabled and pick a Smaily Workflow. The lists come live from your Smaily account and show only enabled workflows whose trigger is form submitted — the only trigger the Smaily API can start. Missing a workflow? Create it in Smaily, then press Refresh workflows.

Not ready yet? Leave the events unticked and continue; you can switch them on later under Settings › Automations.

Seo poe sündmused Smaily automaatikatega. Iga sündmuse — Tervitus, Esimene tellimus, Hüljatud ostukorv — juures märgi Lubatud ja vali Smaily töövoog. Loendid tulevad otse sinu Smaily kontolt ja näitavad ainult lubatud töövooge, mille päästik on form submitted (vorm on esitatud) — see on ainus päästik, mida Smaily API saab käivitada. Töövoog on puudu? Loo see Smailys ja vajuta siis Värskenda töövooge.

Pole veel valmis? Jäta sündmused märkimata ja jätka; saad need hiljem sisse lülitada jaotises Seaded › Automaatikad.

Step 4 — Campaign Intelligence (optional)Samm 4 — Campaign Intelligence (valikuline)

Campaign Intelligence is an optional paid add-on (€250/month) on top of your Smaily monthly payment. Have a setup link from Smaily? Paste it into Setup URL or token from Smaily and press Connect — see Settings › Intelligence for what happens next. Otherwise press Finish; you can connect later.

Separate storefront?

Connecting starts the catalog import at once. Set the Storefront URL on step 1 first, so the import sends your storefront's product links.

Campaign Intelligence on valikuline tasuline lisateenus (250 €/kuus), mis lisandub sinu Smaily kuumaksele. Kas sul on Smailylt saadud seadistuslink? Kleebi see väljale Smailylt saadud seadistus-URL või -võti ja vajuta Ühenda — mis edasi saab, kirjeldab jaotis Seaded › Intelligence. Muul juhul vajuta Lõpeta; saad ühendada hiljem.

Eraldi poe veebileht?

Ühendamine käivitab kohe kataloogi impordi. Sisesta Poe veebilehe aadress esmalt sammul 1, et import saadaks sinu poe veebilehe tootelingid.

Step 5 — OverviewSamm 5 — Ülevaade

You are all set! The last step says that Smaily Connect is syncing — or, if Smaily has not accepted the credentials, that syncing starts once it does, and to check them under Settings > Connection. It lists where everything lives, the address of your product RSS feed and a link to this guide. Go to Dashboard or Open Settings to carry on.

Then check two things: that Magento's cron runs every minute, and that the Dashboard says All systems normal after the first deliveries.

Kõik on valmis! Viimane samm ütleb, et Smaily Connect sünkroonib — või, kui Smaily pole kasutajaandmeid vastu võtnud, et sünkroonimine algab siis, kui ta need vastu võtab, ja et kontrolliksid neid jaotises Seaded > Ühendus. See loetleb, kus mis asub, sinu toodete RSS-voo aadressi ja lingi sellele juhendile. Jätkamiseks vajuta Ava töölaud või Ava seaded.

Seejärel kontrolli kahte asja: et Magento cron käivitub iga minut ja et töölaud ütleb pärast esimesi saadetisi Kõik toimib normaalselt.

ConnectionÜhendus

Abandoned cartHüljatud ostukorv

A cart counts as abandoned when it has products and an email address and has been idle longer than Wait (minutes) (default 30, minimum 10). The store checks for such carts every 5 minutes.

  • A cart older than 24 hours is never mailed, so a cron that was down never sends stale reminders.
  • Each cart is mailed once, and one email address gets at most one reminder in 24 hours, however many carts carry it. A further cart's row in the Log reads Skipped.
  • The email can come from a signed-in customer or from a guest at checkout. On Magento's own checkout (Luma-based themes, and Hyvä's Luma-based checkout) a guest's typed email is saved to the cart two seconds after it becomes a valid address — so a guest who leaves on the shipping step can still be reminded.
  • To stop the checkout being used to put other people's addresses on carts: one IP address can save at most 30 emails in 10 minutes, one cart takes at most five addresses, and the whole store at most 2,000 an hour.
  • The reminder carries up to 10 products and a recovery link, abandoned_cart_url, that restores the exact cart (a registered customer signs in first). The link works for 30 days; after that it opens the cart page with "This cart link has expired."
Avoid two reminders for one cart

Before you switch this automation on, switch off abandoned-cart emails sent by any other tool — for example Mageplaza SMTP, Avada Email Marketing, or Adobe Commerce's own email reminder rules.

Behind a proxy, Varnish or a load balancer?

Make sure Magento sees each shopper's own IP address (nginx real_ip, Apache mod_remoteip, or Magento's RemoteAddress alternativeHeaders setting). Otherwise the 30-in-10-minutes limit counts the whole store as one shopper.

Connecting

  1. Get a one-time setup link from Smaily.
  2. Paste it into Setup URL or token from Smaily and press Connect. The token is exchanged at once and never stored; the status shows the connected account.
  3. Connecting starts the Catalog import: your whole catalog goes to Campaign Intelligence once, from the next cron run (usually within a minute). The notice The catalog import has started offers Hold back the import — press it before then and nothing is sent. Pressed later, the products already queued still go and the rest do not.   4. Connecting starts the Customers import too: your existing customer accounts go to Campaign Intelligence once, after the catalog import, so that it knows every customer by their customer account. The notice The customers import has started says so; to hold it back, press Cancel import on the Customers card under Settings > Intelligence. A customers import already queued or running is left as it is. While Campaign Intelligence is connected and no customers import has ever completed — your store was connected before connecting started this import, or the import was canceled or failed — Magento's System Messages at the top of the admin show Smaily Connect: the customers import has never completed…. The message does not show while a customers import is queued or running, unless the card shows it as Stalled; it is gone for good once one has completed.

The setup link must be an https address on intelligence.smaily.com; anything else is refused before anything is sent. From then on, product saves, stock changes, deletions, customer accounts and orders (including refunds) reach Campaign Intelligence on their own. There is no per-type switch.

Without one the tracker sends nothing. The note under the switch says which source the store has; connect one as described in Connecting your cookie consent tool.

Connecting your cookie consent toolKüpsiste nõusoleku tööriista ühendamine

The browse tracker needs to know whether the visitor allowed marketing cookies. It asks, in this order:

  1. Your own consent function, when the page defines window.smailyConnect.consentOverride. true means consent; any other answer means none.
  2. Magento's cookie notice, when Cookie Restriction Mode is on (Stores > Configuration > General > Web > Default Cookie Settings): consent once the visitor allows cookies there, on that website.
  3. Otherwise there is no consent, and nothing is tracked.

Without consent the tracker sends no event and sets no session cookie. When browse tracking is on and cookie restriction mode is off, the admin shows a notification saying so; a store that uses its own consent function can mark it read. On a store view with a Storefront URL, the separate storefront's own banner decides instead.

Option A — Magento's cookie notice

Switch on Cookie Restriction Mode. Nothing else is needed.

Option B — your own consent tool

Tools such as Amasty Cookie Consent or Cookiebot leave Magento's mode off. Add a small script that answers for your tool — for example under Content > Design > Configuration > (store view) > HTML Head > Scripts and Style Sheets:

  • window.smailyConnect.consentOverride() returns true only when the visitor allowed marketing cookies in your tool.
  • When the visitor changes their choice on the page, fire document.dispatchEvent(new CustomEvent('smaily:consent-changed')); the tracker asks again at once. Without the event, the change counts from the next page view.

Example for Amasty Cookie Consent — put your marketing group's id from Amasty's cookie group settings in place of 3:

<script>
window.smailyConnect = window.smailyConnect || {};
window.smailyConnect.consentOverride = function () {
    var MARKETING_GROUP_ID = '3'; // your marketing group's id in Amasty
    var match = document.cookie.match(/(?:^|; )amcookie_allowed=([^;]*)/);

    return !!match && decodeURIComponent(match[1]).split(',').indexOf(MARKETING_GROUP_ID) !== -1;
};
</script>

Example for Cookiebot:

<script>
window.smailyConnect = window.smailyConnect || {};
window.smailyConnect.consentOverride = function () {
    return !!(window.Cookiebot && window.Cookiebot.consent && window.Cookiebot.consent.marketing);
};
['CookiebotOnConsentReady', 'CookiebotOnAccept'].forEach(function (name) {
    window.addEventListener(name, function () {
        document.dispatchEvent(new CustomEvent('smaily:consent-changed'));
    });
});
</script>

Check the example against the tool version you run.

  1. Sinu enda nõusoleku funktsioonilt, kui leht defineerib window.smailyConnect.consentOverride. true tähendab nõusolekut; iga muu vastus tähendab, et nõusolekut pole.
  2. Magento küpsiste teatelt, kui Cookie Restriction Mode (küpsiste piirangurežiim) on sees (Stores > Configuration > General > Web > Default Cookie Settings): nõusolek on olemas, kui külastaja on seal küpsised lubanud, sellel veebisaidil.
  3. Muul juhul nõusolekut pole ja midagi ei jälgita.

Recommendation attributionSoovituste omistamine

When a shopper arrives from a recommendation link in a Smaily email, the link's parameters (smaily_rec, smaily_vt, smaily_ctx) are kept in first-party cookies and added to the order, so Campaign Intelligence can credit the purchase to the recommendation. It runs on its own once Campaign Intelligence is connected — nothing to switch on — and works with full-page cache. The last click wins. A malformed value (for example from a test email's placeholder) is ignored; the order still reaches Campaign Intelligence.

Kui ostja saabub Smaily e-kirjas olnud soovituslingilt, hoitakse lingi parameetrid (smaily_rec, smaily_vt, smaily_ctx) esimese osapoole küpsistes ja lisatakse tellimusele, et Campaign Intelligence saaks ostu soovitusele omistada. See töötab ise, kui Campaign Intelligence on ühendatud — midagi pole vaja sisse lülitada — ja toimib ka lehevahemäluga. Kehtib viimane klikk. Recommendations on your store's pagesSoovitused poe lehtedel

The Smaily recommendations widget shows a shopper their own recommendations from Campaign Intelligence — the same products as in their Smaily emails — on your store's pages, under the heading Recommended for you, as your theme's own product cards. Nothing appears until you place the widget, and it has no settings.

  1. Open a page under Content > Pages or a block under Content > Blocks.
  2. In the content editor press Insert Widget..., pick Smaily recommendations as the Widget Type and press Insert Widget. In Page Builder do the same in a Text element, or put {{widget type="Smaily\Connect\Block\Widget\Recommendations"}} in an HTML Code element.
  3. Save the page or block.
  • Who sees what: a signed-in customer sees their recommendations unless they opted out of personalized recommendations or unsubscribed from your newsletter; a guest sees them only after an earlier click on a Smaily email link. A shopper Campaign Intelligence has nothing for, a new visitor or a shopper without marketing consent sees nothing — not even the heading.
  • The cards: up to four products with your store's own name, image and price. A product that is disabled, not visible in the catalog, not in this website or not for sale is left out. A purchase after a click on a card is credited to your store's pages.
  • Consent: the same rules as the browse tracker (Cookie consent tool). Consent given on the page shows the recommendations at once.
  • Speed: the page stays in the full-page cache and the cards are asked for after it has loaded, so the page never waits. A shopper's recommendations are kept for an hour, so a new one can take up to an hour to show. When Campaign Intelligence does not answer, nothing shows and the store asks again after 10 minutes.
  • Nothing shows while Campaign Intelligence is not connected or the account is deactivated. Hyvä needs the Hyvä compatibility module; a separate storefront does not get the widget.

Vidin Smaily soovitused näitab ostjale poe lehtedel tema enda soovitusi Campaign Intelligence'ist — samu tooteid, mis on tema Smaily e-kirjades — pealkirja Sulle soovitatud all, sinu teema enda tootekaartidena. Midagi ei ilmu enne, kui vidina lehele paigutad, ja sellel pole seadeid.

  1. Ava leht menüüs Content > Pages või plokk menüüs Content > Blocks.
  2. Vajuta sisuredaktoris Insert Widget..., vali Widget Type väärtuseks Smaily soovitused ja vajuta Insert Widget. Page Builderis tee sama elemendis Text või pane {{widget type="Smaily\Connect\Block\Widget\Recommendations"}} elementi HTML Code.
  3. Salvesta leht või plokk.
  • Kes mida näeb: sisse logitud klient näeb oma soovitusi, kui ta pole personaalsetest soovitustest loobunud ega uudiskirjast lahkunud; külaline näeb neid ainult pärast varasemat klikki Smaily e-kirja lingil. Ostja, kellele Campaign Intelligence'il soovitusi pole, uus külastaja või turundusnõusolekuta ostja ei näe midagi — ka pealkirja mitte.
  • Kaardid: kuni neli toodet sinu poe enda nime, pildi ja hinnaga. Toode, mis on välja lülitatud, kataloogis nähtamatu, pole selles veebisaidis või pole müügil, jäetakse välja. Ost pärast kaardil klikkimist omistatakse sinu poe lehtedele.
  • Nõusolek: samad reeglid nagu sirvimise jälgijal (Küpsiste nõusoleku tööriist). Lehel antud nõusoleku järel ilmuvad soovitused kohe.
  • Kiirus: leht jääb lehevahemällu ja kaarte küsitakse pärast lehe laadimist, nii et leht ei oota kunagi. Ostja soovitusi hoitakse tund aega, seega võib uue soovituse ilmumiseks kuluda kuni tund. Kui Campaign Intelligence ei vasta, ei näidata midagi ja pood küsib uuesti 10 minuti pärast.
  • Midagi ei näidata, kui Campaign Intelligence pole ühendatud või konto on deaktiveeritud. Hyvä vajab Hyvä ühilduvusmoodulit; eraldi poe veebileht vidinat ei saa.

If your Campaign Intelligence account is deactivatedKui sinu Campaign Intelligence'i konto on deaktiveeritud

If Smaily suspends or closes the Campaign Intelligence account behind your store, the engine stops accepting data and the extension stops sending:

  • Nothing is lost: everything queued stays queued and goes out once the account is active again.
  • Settings > Intelligence says the account is not active, links to your Smaily account and offers Check again. The Campaign Intelligence imports and automations are unavailable meanwhile.
  • The Dashboard and an admin notification name the deactivated account. Waiting does not fix it — only Smaily can make the account active again.
  • Your Smaily contact sync and email automations are not affected.

Once Smaily tells you the account is active, press Check again. The store also asks again on its own every 15 minutes.

Kui Smaily peatab või sulgeb sinu poe taga oleva Campaign Intelligence'i konto, lõpetab mootor andmete vastuvõtmise ja laiendus lõpetab saatmise:

  • Midagi ei lähe kaduma: kõik järjekorras olev jääb järjekorda ja saadetakse, kui konto on taas aktiivne.
  • Seaded > Intelligence ütleb, et konto ei ole aktiivne, lingib sinu Smaily kontole ja pakub nuppu Kontrolli uuesti. Campaign Intelligence'i impordid ja automaatikad pole seni kasutatavad.
  • Töölaud ja halduse teade nimetavad deaktiveeritud kontot. Ootamine seda ei lahenda — ainult Smaily saab konto taas aktiivseks teha.
  • Sinu Smaily kontaktide sünkroonimist ja e-posti automaatikaid see ei mõjuta.

Kui Smaily on öelnud, et konto on aktiivne, vajuta Kontrolli uuesti. Pood küsib ka ise iga 15 minuti järel uuesti.

The nightly product checkÖine tootekontroll

Once a night at 03:30 (your store's time zone), the extension sends Campaign Intelligence the list of all your products — each product's SKU and whether it is in stock, nothing else. Campaign Intelligence then:

  • stops recommending a product missing from the list (for example one deleted straight in the database);
  • takes the stock from the list where it differs (a product found back in stock this way sends no back-in-stock email);
  • counts products it does not have, so Smaily's team sees that a catalog import is needed.

Disabled products are left out, so they stop being recommended. If the list would remove more than a fifth of your products, or is empty, nothing is removed and Smaily's team checks it. The check waits for another night while the catalog import is running (a catalog import set aside as stalled does not hold it back, even while other imports run), while product changes still wait in the Log, or while Campaign Intelligence is not connected or active. A store with more than 50,000 enabled products cannot use it yet.

Each list sent shows in the Log as one catalog_manifest row; Details shows Campaign Intelligence's answer. If no list has gone out for three nights, the Dashboard says so and why.

Igal ööl kell 03:30 (sinu poe ajavööndis) saadab laiendus Campaign Intelligence'ile kõigi sinu toodete loendi — iga toote SKU ja kas see on laos, muud mitte. Seejärel Campaign Intelligence:

  • lõpetab loendist puuduva toote soovitamise (näiteks otse andmebaasis kustutatud toote);
  • võtab erineva laoseisu loendist (nii laos tagasi olevaks leitud toote kohta ei saadeta „taas laos“ kirja);
  • loendab tooted, mida tal pole, et Smaily meeskond näeks, et kataloogi import on vajalik.

Keelatud tooted jäetakse välja, nii et neid enam ei soovitata. Kui loend eemaldaks üle viiendiku sinu toodetest või on tühi, ei eemaldata midagi ja Smaily meeskond kontrollib seda. Kontroll ootab järgmist ööd, kui kataloogi import töötab (seiskunuks märgitud kataloogi import seda ei takista, ka siis, kui teised impordid töötavad), kui tootemuudatused ootavad logis veel saatmist või kui Campaign Intelligence pole ühendatud või aktiivne. Pood, kus on üle 50 000 lubatud toote, ei saa seda veel kasutada.

Iga saadetud loend on logis üks rida catalog_manifest; Üksikasjad näitab Campaign Intelligence'i vastust. Kui kolm ööd järjest pole loendit saadetud, ütleb töölaud seda koos põhjusega.

Failed rows and retryEbaõnnestunud read ja kordus

  • Automatic retry. A delivery that fails for a passing reason is tried again after 1, 5, 15 and 60 minutes — 5 attempts over about 81 minutes — before it is marked Failed. When Smaily asks the store to slow down, the row waits as long as asked.
  • No retry. A delivery that was refused outright — wrong credentials, a deleted workflow, data Smaily or Campaign Intelligence calls invalid — is marked Failed at once, so you see it now.
  • Retry — select failed rows in the grid and choose Retry. Rows that cannot safely be sent again are left alone and counted ("… skipped because sending again would not be safe").
  • Send again — on one failed row (in the grid or in Details), queues a new attempt as a new row; the failed row stays as your record.
  • No Send again button? Sending again would reach the shopper twice or reach nobody: the reminder was withdrawn, a later message of the same kind already reached the contact, the contact's data was erased, or it is a nightly product list (built afresh each night).

Fix the cause first (see the tables above), then retry.

  • Automaatne kordus. Mööduval põhjusel ebaõnnestunud saadetist proovitakse uuesti 1, 5, 15 ja 60 minuti pärast — 5 katset umbes 81 minuti jooksul —, enne kui see märgitakse Ebaõnnestunud. Kui Smaily palub poel aeglustada, ootab rida nii kaua, kui palutud.
  • Kordust pole. Otse tagasi lükatud saadetis — valed kasutajaandmed, kustutatud töövoog, andmed, mida Smaily või Campaign Intelligence nimetab vigaseks — märgitakse kohe Ebaõnnestunud, et näeksid seda kohe.
  • Proovi uuesti — vali tabelis ebaõnnestunud read ja vali Proovi uuesti. Read, mida pole ohutu uuesti saata, jäetakse puutumata ja loendatakse („… jäeti vahele, sest uuesti saatmine poleks ohutu“).
  • Saada uuesti — ühel ebaõnnestunud real (tabelis või jaotises Üksikasjad) paneb uue katse järjekorda uue reana; ebaõnnestunud rida jääb sinu jaoks ajaloona alles.
  • Nuppu „Saada uuesti“ pole? Uuesti saatmine jõuaks ostjani kaks korda või ei jõuaks kellenigi: meeldetuletus võeti tagasi, sama liiki hilisem kiri on kontaktini juba jõudnud, kontakti andmed on kustutatud või on tegu öise tootenimekirjaga (koostatakse igal ööl uuesti).

Nothing is syncingMidagi ei sünkroonita

  1. Is cron running? Run bin/magento cron:run --group smaily_connect once by hand; if rows in the Log then move from Pending, Magento's cron is not set up to run every minute.
  2. Is Smaily connected? The Dashboard says Not connected when Smaily has not accepted the saved credentials.
  3. Is contact sync on? Sync contacts to Smaily on Settings > Contacts, for the right website. Under Checkout opt-in only, only checkout signups sync.
  4. What does the Log say? Filter on Failed and read Last Error — see The Log, error messages & fixes.
  1. Kas cron töötab? Käivita üks kord käsitsi bin/magento cron:run --group smaily_connect; kui read logis liiguvad siis olekust Ootel edasi, pole Magento cron seadistatud iga minut käivituma.
  2. Kas Smaily on ühendatud? Töölaud ütleb Pole ühendatud, kui Smaily pole salvestatud kasutajaandmeid vastu võtnud.
  3. Kas kontaktide sünkroonimine on sees? Sünkrooni kontaktid Smailysse jaotises Seaded > Kontaktid, õige veebisaidi jaoks. Režiimis Ainult kassas turunduskirjade nõusoleku andnud kontaktid sünkroonitakse ainult kassas liitujad.

The abandoned-cart email never arrivesHüljatud ostukorvi kiri ei jõua kohale

  • The automation is Enabled with a workflow picked, for the cart's website (and language).
  • The cart has an email address: a signed-in customer's, or a guest's typed on the checkout's email field.
  • The cart has been idle longer than Wait (minutes), but less than 24 hours.
  • The cart was not reminded already, and the address got no reminder for another cart in the last 24 hours (that row reads Skipped).

  • Ostukorv on olnud puutumata kauem kui Ooteaeg (minutites), kuid vähem kui 24 tundi.

How do I disconnect Campaign Intelligence?Kuidas Campaign Intelligence'i lahti ühendada?

From the command line: bin/magento smaily:engine:disconnect --force. It removes the store's connection; data already in Campaign Intelligence stays there, and the API key stays valid on the engine until Smaily revokes it. Connecting again needs a new setup link from Smaily. To stop Smaily syncing for a website, switch off Sync contacts to Smaily and the automations.

Käsurealt: bin/magento smaily:engine:disconnect --force. See eemaldab poe ühenduse; Campaign Intelligence'is juba olevad andmed jäävad sinna ja API võti kehtib mootoris, kuni Smaily selle tühistab. Does disabling or removing the extension delete my data?Kas laienduse keelamine või eemaldamine kustutab andmed?

  • Disabling stops everything at once. On the next setup:upgrade, Magento drops the extension's tables — the queues (including anything not yet sent), the Log, the abandoned-cart tracker and the import progress. Your settings are kept.
  • Uninstalling also removes the settings (the encrypted Smaily password and Campaign Intelligence key included) and the record of personalization opt-outs.
  • Nothing is deleted in Smaily or Campaign Intelligence. Contacts and data already there stay.

The commands are in INSTALLING.md › Disabling or removing the module.

  • Keelamine peatab kohe kõik. Järgmisel käsul setup:upgrade kustutab Magento laienduse tabelid — järjekorrad (koos veel saatmata kirjetega), logi, hüljatud ostukorvide jälgija ja impordi edenemise. Sinu seaded säilivad.
  • Eemaldamine (uninstall) kustutab ka seaded (koos krüpteeritud Smaily parooli ja Campaign Intelligence'i võtmega) ning personaliseerimisest loobumiste kirje.
  • Smailys ja Campaign Intelligence'is ei kustutata midagi. Seal juba olevad kontaktid ja andmed jäävad alles.

Käsud on juhendis INSTALLING.md › Disabling or removing the module (inglise keeles).

Personalization opt-outPersonaliseerimisest loobumine

Personalized recommendations are on by default. A customer can switch them off under My Account > Personalization: untick Allow personalized recommendations and press Save Preference. The page exists only while Campaign Intelligence is connected and active. If the store cannot read the preference at that moment, the page offers a single Opt out of personalized recommendations button instead.

  • The choice is kept by the store, written onto the Smaily contact (smaily_rec_profiling) when Smaily has one, and sent to Campaign Intelligence as a queued delivery (engine.profiling_consent in the Log), so an outage only delays it.
  • A newsletter unsubscribe — in the store, or in Smaily and mirrored back — also turns personalization off; subscribing again turns it back on, unless the shopper opted out separately.
  • An opted-out shopper's browsing is not linked to their account at login.
  • An admin using Login as Customer, or creating an order in the admin, links no browsing and credits no recommendation.

Personaalsed soovitused on vaikimisi sees. Klient saab need välja lülitada lehel Minu konto > Personaliseerimine: eemalda märge Luba personaalsed soovitused ja vajuta Salvesta eelistus. Leht on olemas ainult siis, kui Campaign Intelligence on ühendatud ja aktiivne. Kui pood ei saa eelistust sel hetkel lugeda, pakub leht selle asemel ühte nuppu Loobu personaalsetest soovitustest.

Export and erasure (GDPR)Eksport ja kustutamine (GDPR)

For a data subject request, run on the server:

bin/magento smaily:gdpr export shopper@example.com          # Art. 15: prints JSON
bin/magento smaily:gdpr erase shopper@example.com --force   # Art. 17

Both cover the shopper's record in Campaign Intelligence and the extension's own tables — the two delivery queues and the abandoned-cart tracker. The erasure:

  • deletes queued messages not yet sent, so nothing more goes out;
  • anonymizes sent and failed rows — they keep their type, status and times as your record, with the address and contents replaced by [erased], and can no longer be retried. They are removed on their normal schedule: 30 days after the delivery, 90 days after the failure;
  • marks the shopper's carts as erased, so no abandoned-cart reminder goes out for them. The mark stays while the cart is still open in the store; once the cart is ordered or closed, the nightly tidy-up removes it 30 days after its last change before the erasure, or sooner if Magento deletes the cart;
  • erases the shopper in Campaign Intelligence.

It prints one line per place it reached. The local part runs first; if Campaign Intelligence is unreachable or the account is deactivated, the command says so — run it again later to finish. Running it twice is harmless.

The command does not touch Magento's own customer data (use Magento's tools) or the Smaily contact (delete it in Smaily).

Andmesubjekti taotluse korral käivita serveris:

bin/magento smaily:gdpr export shopper@example.com          # art 15: väljastab JSON-i
bin/magento smaily:gdpr erase shopper@example.com --force   # art 17

Mõlemad hõlmavad ostja kirjet Campaign Intelligence'is ja laienduse enda tabeleid — kahte saatmisjärjekorda ja hüljatud ostukorvide jälgijat. Kustutamine:

  • kustutab järjekorras olevad saatmata kirjed, nii et midagi enam teele ei lähe;
  • anonüümib saadetud ja ebaõnnestunud read — need säilitavad sinu tõendina tüübi, oleku ja ajad, aadress ja sisu asendatakse väärtusega [erased] ning neid ei saa enam uuesti proovida. Need eemaldatakse tavapärase ajakava järgi: 30 päeva pärast kohaletoimetamist, 90 päeva pärast ebaõnnestumist;
  • märgib ostja ostukorvid kustutatuks, nii et nende kohta hüljatud ostukorvi meeldetuletust ei saadeta. Märge jääb alles, kuni ostukorv on poes veel avatud; kui ostukorv on tellitud või suletud, eemaldab öine korrastus selle 30 päeva pärast viimast muudatust enne kustutamist, või varem, kui Magento ostukorvi kustutab;
  • kustutab ostja Campaign Intelligence'ist.

See väljastab ühe rea iga koha kohta, kuhu jõudis. Kohalik osa käib esimesena; kui Campaign Intelligence on kättesaamatu või konto deaktiveeritud, ütleb käsk seda — käivita see hiljem uuesti, et lõpetada. Kahekordne käivitamine ei tee kahju.

Käsk ei puuduta Magento enda kliendiandmeid (kasuta Magento tööriistu) ega Smaily kontakti (kustuta see Smailys).

Upgrading from Smaily for Magento 2.8.xUuendamine versioonilt Smaily for Magento 2.8.x

Version 3 replaces the 2.8.x module, but the composer package name is the same and your settings migrate automatically. Write down your 2.8.x settings first. composer update alone stays on 2.8.x, so require version 3. Until 3.0.0 is released, the commands give the release candidate's exact version, as the releases page names it: ^3.0 does not install a release candidate on a standard Magento project, which accepts stable versions only. From 3.0.0 on, composer require smaily/smailyformagento:^3.0 is enough. In production mode:

bin/magento maintenance:enable
composer require smaily/smailyformagento:3.0.0-rc10
bin/magento setup:upgrade
bin/magento setup:di:compile
bin/magento setup:static-content:deploy en_US   # every locale your store uses
bin/magento maintenance:disable
bin/magento cache:flush

In developer or default mode, composer require, setup:upgrade and cache:flush are enough.

  • The admin notification says the earlier settings were migrated. Every Marketing > Smaily Connect page opens the Initial setup until it is finished for the website; it shows the migrated settings — check them against your notes. For a website where 2.8.x had Enable Module = No, contact sync stays off: its Contacts step shows Sync contacts to Smaily unticked, and Continue keeps it off. Tick it there to switch contact sync on.
  • The old newsletter captcha is not carried over — use Magento's own reCAPTCHA for newsletter forms.
  • The sync-frequency setting is gone: changes sync as they happen.
  • Switch off any other abandoned-cart emails before switching the Smaily one on.
